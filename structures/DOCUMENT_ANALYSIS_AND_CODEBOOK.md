# 🏷️ Document Analysis, Coding Manual & Inter-Coder Agreement

> **How to turn a corpus of documents into findings: sampling, a codebook, double-coding and reporting.**
> The corpus study on essential requirements is a document analysis. Its credibility rests on three things a reviewer will check: how documents were sampled and captured, how the codes were defined, and whether a second person coding independently agreed.

---

## 1. The structure

| Part | What it does | Notes |
|---|---|---|
| Sampling frame | Which documents, from where, and why | Stratify so no one province or profession dominates |
| Capture protocol | How each document is saved and dated | PDF plus Internet Archive link the same day |
| Codebook | Each code: name, definition, inclusion, exclusion, example, counter-example | The single most important document |
| Pilot coding | Code a subset, revise the codebook, freeze it | Expect splits and a new value |
| Second coder | Independent coding of a subsample; agreement computed | Krippendorff's alpha or Cohen's kappa |
| Analysis | Frequencies, cross-tabs, and illustrative quotations | Report in aggregate |
| Reporting | Method, codebook, agreement, limits | SRQR items as the checklist |

---

## 2. How to do it well

1. Write the codebook before coding the full set, and give every code a counter-example.
2. Pilot on twenty, revise, then preregister the frozen codebook.
3. Train the second coder on documents outside the sample, then code ten independently; resolve disagreements by discussion and report both pre- and post-discussion agreement.
4. Keep a memo log of every judgement call; it becomes the limitations section.
5. Report institutions in aggregate with unattributed quotations.
